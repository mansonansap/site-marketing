# Marketing CV + admin

Компактный сайт маркетолога и настоящая серверная админка. Профиль, фото, опыт, ссылки, статьи, проекты и тексты на RU / EN / UA / ES редактируются в браузере. Сохранённые правки отделены от опубликованного сайта.

## Запуск

Нужны Node.js 20+ и терминал. Зависимостей npm и отдельной базы данных нет.

```sh
npm run dev
```

Сайт обслуживается на порту 3000, админка — по пути `/admin/`. Для локальной проверки откройте адрес сервера в браузере. Старый Python HTTP-сервер больше не нужен: для сохранения контента должен работать Node.js-сервер.

### Первый администратор

В другом терминале, из каталога проекта:

```sh
npm run admin:create
```

Введите логин и пароль (не менее 12 символов), затем подтвердите пароль. Ввод пароля скрыт. Команда сохраняет scrypt-хеш; пароли не попадают в исходники и не выводятся. По умолчанию администратора нет, публичная регистрация отсутствует.

Откройте `/admin/` и войдите. Этой же командой можно сменить логин/пароль: после смены предыдущие сессии перестают работать. Если используется `DATA_DIR`, задайте тот же путь при запуске команды создания администратора.

## Что есть в админке

- **Профиль и фото:** имя, email, общий стаж, загрузка фотографии, описание на четырёх языках, ссылки и социальные сети.
- **Опыт:** добавление и удаление записей, компания, должность или направление, период, описание, список задач/достижений, значок и связанная статья.
- **Статьи:** отдельные заголовки, описания и тексты, категории, дата, время чтения, обложки, переводы, черновики и включение в публикацию.
- **Проекты:** контекст, подход, результаты, переводы, обложка и собственный URL.
- **Тексты сайта:** навигация, кнопки, подписи, блок контактов, SEO-описание и уведомления.
- Экспорт контента в JSON и восстановление из файла. Изображения экспортируются отдельно вместе с каталогом данных.

Тексты вводятся как обычный текст. Статья состоит из разделов «заголовок + текст»; переносы строк сохраняются. HTML из редактора не выполняется. Для опыта и материалов пустые переводы используют RU.

### Как публиковать

1. Отредактируйте нужные разделы.
2. Нажмите **Сохранить** — правки сохранятся на сервере, сайт останется прежним.
3. Нажмите **Предпросмотр** — откроется закрытая версия с сохранёнными правками.
4. Нажмите **Опубликовать** — сохранённая версия станет доступна посетителям.

«Предпросмотр» и «Опубликовать» сначала сохраняют текущие правки. Черновик статьи/проекта появится на сайте только при установленном флажке «Включить на сайте» и общей публикации. Если поменять URL или удалить материал, старый адрес после публикации вернёт 404.

## Хранение

По умолчанию сервер создаёт игнорируемый Git каталог `.data/`:

```text
.data/
  content.json       # сохранённый черновик
  published.json     # опубликованный снимок
  auth.json          # имя администратора, соль и scrypt-хеш
  uploads/           # загруженные изображения
  backups/           # последние 20 копий контента перед сохранением
  releases/          # временные сгенерированные страницы
```

Тексты, картинки и учётная запись переживают перезапуск. Сессии хранятся в памяти и при перезапуске заканчиваются. Старые сгенерированные выпуски очищаются автоматически. Изображения не удаляются автоматически при удалении ссылки на них, чтобы не сломать опубликованную версию и резервные копии.

**Сделайте резервную копию всего каталога данных**, включая `uploads/` и `auth.json`. Не публикуйте его в Git, не кладите в публичный каталог статического хостинга и не выводите содержимое `auth.json`.

`site-data.mjs` и `cv-copy.mjs` задают начальный контент при первом запуске. После создания `.data/` источником текущего контента становится админка. Изменение исходных демонстрационных данных не перезаписывает уже сохранённые материалы.

## Размещение на хостинге

Пошаговая инструкция для Ubuntu VPS Namecheap: [DEPLOY.md](DEPLOY.md). Для VPS подготовлены Dockerfile, compose.yaml, Caddyfile и .env.example; рекомендуемый вариант для пустого Ubuntu VPS — Docker + Caddy.

Нужен хостинг с работающим Node.js и **постоянным диском**. Публичный сайт и API обслуживаются одним процессом и доменом. Одного статического хостинга без серверной части для админки недостаточно.

Пример переменных:

```text
NODE_ENV=production
PORT=3000
HOST=0.0.0.0
DATA_DIR=/путь/к/постоянному/каталогу
PUBLIC_ORIGIN=https://your-domain.example
```

`PUBLIC_ORIGIN` — точный публичный origin без завершающего слеша; полезен за обратным прокси. Хостинг должен направлять запросы домена в Node.js и обеспечивать HTTPS. В production используются Secure-cookie. При доверенном HTTPS-прокси можно дополнительно задать `TRUST_PROXY=1`; не включайте это для прямых недоверенных запросов.

Команда запуска:

```sh
npm start
```

Создайте администратора на хостинге командой `npm run admin:create` с тем же `DATA_DIR`. Восстановление существующего каталога данных сохраняет учётную запись.

Не размещайте production-данные на эфемерном диске: такой хостинг может удалить их при перезапуске или новом деплое. Для этой файловой реализации используйте один серверный процесс/экземпляр на каталог данных. Горизонтальное масштабирование требует отдельного общего хранилища/БД.

## Адреса

- `/` — CV.
- `/journal/` — журнал с фильтрами.
- `/journal/<slug>/` — статья.
- `/work/` — проекты.
- `/work/<slug>/` — кейс.
- `/admin/` — редактор с входом.
- `/admin/preview/` — закрытый предпросмотр после его подготовки.
- `/healthz` — проверка доступности сервера.

Шрифты хранятся локально в `assets/fonts` с лицензиями SIL OFL. Внешние API и ключи не нужны. Небольшие значки платформ обозначают маркетинговые каналы, а не сертификаты или партнёрство.

## Разработка

```sh
npm run check
npm test
```

Тесты проверяют вход, сессии, защиту изменений, изображения, изоляцию черновиков, предпросмотр, публикацию, удаление страниц, пустые разделы, конфликты сохранения и сохранность после перезапуска. Они используют временный каталог и тестовую учётную запись, не меняя настоящие данные.

`npm run build` создаёт статический дизайн-снимок из начальных исходников. Рабочий сервер рендерит страницы из опубликованного содержимого `.data/published.json`; ручная правка сгенерированного `index.html` не является способом редактирования CMS.

Основные файлы:

- `server.mjs` — HTTP-сервер, API, загрузки и публикация;
- `cms/content.mjs` — валидация, атомарное сохранение, версии и резервные копии;
- `cms/auth.mjs` — пароли, сессии и ограничения входа;
- `admin/` — редактор;
- `scripts/build.mjs` — шаблоны публичных страниц;
- `style.css`, `app.js` — внешний вид и поведение сайта;
- `test/cms.test.mjs` — серверные проверки.

Демонстрационные статьи и кейсы помечены в начальных данных. После добавления своих материалов снимите соответствующую пометку. Email `contact@examle.com` сохранён по запросу как пример; замените его на настоящий в админке.
