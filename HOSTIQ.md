# Установка на HOSTiQ HQ20: PHP + MariaDB

Это самостоятельная PHP-версия текущего сайта. Node.js, Docker, Composer,
Passenger и команды со старого VPS для неё не нужны. Дизайн, четыре языка,
редактирование контента, фотографии, проекты, статьи, предпросмотр,
публикация и обращения сохранены. Все серверные операции выполняет PHP.

## 1. Подготовка

1. В cPanel → «Домени» добавьте купленный домен, если его ещё нет.
   Посмотрите **корневую папку документа (Document Root)** этого домена.
   Для основного домена обычно это `/home/CPANEL_LOGIN/public_html`.
2. Настройте DNS по данным HOSTiQ. Если домен обслуживается их DNS,
   проверьте A-запись домена: она должна указывать на IP вашего хостинга
   (на момент настройки пользователь получил `193.111.62.7`). Не используйте IP старого VPS.
   `www`, если нужен, должен вести на тот же сайт.
3. В cPanel → «Вибір версії PHP» выберите **PHP 8.2 или новее**, рекомендуется 8.3.
   Включите `pdo_mysql`, `mbstring`, `fileinfo`; `session` и `json` тоже необходимы.
   В параметрах PHP установите `post_max_size` и `upload_max_filesize` не меньше `10M`,
   `memory_limit` не меньше `128M`. Если параметр недоступен — попросите поддержку.
4. В «SSL/TLS Status» выпустите AutoSSL для домена и дождитесь работы HTTPS.
   В «Домени» включите Force HTTPS Redirect. Используйте один основной адрес:
   с `www` либо без. В дальнейших шагах укажите точно этот адрес.
5. **Не регистрируйте приложение в «Менеджері додатків».** Passenger не используется.
   Если ранее уже регистрировали приложение на этот домен, снимите его регистрацию.
6. Если в папке домена есть старый сайт, скачайте его резервную копию и сохраните
   старый `.htaccess` перед заменой. Не распаковывайте архив поверх неизвестного сайта.

## 2. Создание базы

1. cPanel → «MySQL Database Wizard / Майстер баз даних MySQL» (или Manage My Databases).
2. Создайте базу, например `marketing`. Полное имя будет вроде `LOGIN_marketing`.
3. Создайте отдельного пользователя БД с сильным паролем. Сохраните пароль у себя.
4. Привяжите пользователя к базе и выдайте **ALL PRIVILEGES** только на эту базу.
5. Запишите полные имена базы и пользователя с префиксом cPanel. Хост базы
   обычно `localhost`; используйте значение HOSTiQ, если поддержка укажет другое.

## 3. Загрузка

Скачайте готовый архив из репозитория:

https://github.com/mansonansap/site-marketing/raw/refs/heads/main/releases/hostiq-site.zip

Если браузер открыл страницу файла, нажмите Download raw file в GitHub.
Архив содержит `public_html/`, `marketing-cv-private/` и эту инструкцию.

1. В cPanel → «Диспетчер файлів» откройте **домашний каталог** `/home/LOGIN`,
   то есть уровень выше `public_html`.
2. Загрузите `hostiq-site.zip` именно туда и распакуйте.
3. Если Document Root домена — `public_html`, структура уже готова:
   - `/home/LOGIN/public_html/index.php`, `.htaccess`, `style.css`, `app.js`, `admin/`, `assets/`;
   - `/home/LOGIN/marketing-cv-private/` с PHP-кодом и настройками.
4. Если Document Root другой, перенесите **содержимое** папки из архива `public_html/`
   в Document Root нужного домена. В его `index.php` замените строку `$private = ...` на:
   ```php
   $private = '/home/LOGIN/marketing-cv-private';
   ```
   Укажите свой реальный путь; оставьте приватную папку вне всех Document Root.
5. В настройках диспетчера включите показ скрытых файлов и убедитесь, что `.htaccess`
   попал в папку домена. Он направляет запросы к PHP и запрещает листинг каталогов.
6. Удалите загруженный ZIP из хостинга после распаковки. Приватные настройки
   не размещайте в `public_html`, не загружайте в публичный GitHub.

## 4. Настройки

В `/home/LOGIN/marketing-cv-private/` скопируйте `config.example.php` в `config.php`.
Через «Редагувати» заполните:

```php
<?php
return [
    'db_host' => 'localhost',
    'db_port' => 3306,
    'db_name' => 'LOGIN_marketing',
    'db_user' => 'LOGIN_marketer',
    'db_password' => 'ВАШ_ПАРОЛЬ_БАЗЫ',
    'origin' => 'https://ВАШ-ДОМЕН',
    'setup_key' => 'ВАШ_СЛУЧАЙНЫЙ_СЕКРЕТ_НЕ_КОРОЧЕ_32_СИМВОЛОВ',
];
```

- `origin` — точный HTTPS-адрес, без слеша в конце, без пути.
- `setup_key` сгенерируйте в менеджере паролей: например 48 случайных латинских
  букв и цифр. Он понадобится только для создания администратора.
- Значения в PHP заключены в одинарные кавычки. Если пароль содержит `'` или `\`,
  перед таким символом нужен обратный слеш. Можно сгенерировать длинный пароль
  БД из букв и цифр, чтобы не ошибиться при вставке.
- Доступ к приватной папке/файлам — только владельцу: обычно `700` для папки
  и `600` для config.php. Не ставьте `777`. В cPanel PHP работает от вашего пользователя;
  если провайдер требует иные права, уточните у поддержки.

## 5. Первый вход

1. Откройте `https://ВАШ-ДОМЕН/install.php`.
2. Введите `setup_key`, придумайте логин и пароль администратора
   (от 12 до 72 байт; латинские символы удобнее для однозначной длины).
3. Нажмите «Установить». Таблицы создадутся автоматически, затем откроется `/admin/`.
   Установщик не заменяет существующий сайт: после создания администратора он блокируется.
4. Войдите в админку. Откройте сайт и проверьте главную, `/journal/`, `/work/`.
5. Добавьте фото/тексты → «Сохранить» → «Предпросмотр» → «Опубликовать».
6. Отправьте пробное обращение на сайте и проверьте «Обращения» в админке.

Пароль БД, setup_key и пароль администратора в чат не присылайте.

## 6. Если сохранились данные старого сайта

Код из GitHub не содержит изменений, сделанных в прежней админке.

- Если есть JSON-экспорт контента: в новой админке «Тексты сайта» →
  «Восстановить из файла» → проверить → сохранить → опубликовать.
- Если есть `.data/content.json` или `published.json` со старого VPS:
  это совместимый формат для такого же импорта. `content.json` может содержать
  неопубликованные правки; `published.json` — последнюю опубликованную версию.
- Фото из старой `.data/uploads/` скопируйте с теми же именами в
  `marketing-cv-private/uploads/`. Ссылки `/uploads/...` продолжат работать.
- Старый пароль администратора не переносится: используйте новый аккаунт.
- Старые обращения из `.data/inbox/` автоматически не импортируются. Если такая
  копия есть, сохраните её: для переноса нужен отдельный импорт в базу.
- Если резервной копии нет, сайт стартует с исходными демонстрационными данными.

## 7. Резервные копии и обновления

Регулярно сохраняйте **оба**:
1. Экспорт MariaDB через phpMyAdmin — черновик, опубликованный контент,
   администратор, обращения и последние 20 версий контента.
2. Приватную папку `marketing-cv-private/`, включая `uploads/` и `config.php`.

JSON-копия из админки содержит только контент, без фото и обращений.

При обновлении заменяйте код и публичные файлы из нового архива, сохраняя
`config.php`, `uploads/` и базу. Не запускайте установку повторно и не удаляйте таблицы.

## Ошибки

- 500 / ошибка базы: проверьте полные имена БД/пользователя, пароль,
  привязку пользователя к базе и журнал ошибок cPanel.
- «Нужны PHP…»: выберите подходящую версию PHP и расширения.
- Главная работает, внутренние URL дают 404: проверьте наличие `.htaccess`
  и поддержку Apache mod_rewrite/AllowOverride у провайдера.
- 403 при входе/отправке: проверьте `origin` и открывайте сайт именно по этому
  адресу, включая https и выбранный www. Для иного домена настройте редирект в cPanel.
- 429: сработал лимит попыток; подождите 15 минут. Лимиты хранятся в базе,
  перезапуск хостинга их не сбрасывает.

## Для разработчика

PHP-исходники: `php-hosting/`. Общие CSS/JS/шрифты берутся из основного проекта.
Пересборка готового ZIP на рабочей машине: `node scripts/package-php.mjs`.
На хостинге эта команда не нужна. Для локальной проверки используется
`test/php/Dockerfile` и Apache + MariaDB 10.11; Docker нужен только разработчику.

Команды проверки на рабочей машине:

```bash
npm run package:php
BUILDX_CONFIG=/tmp/marketing-cv-buildx docker build -t marketing-cv-php:test -f test/php/Dockerfile .
docker pull mariadb:10.11
npm run test:php
```

Интеграционный тест создаёт временные Apache/MariaDB-контейнеры, случайные
тестовые пароли и отдельную сеть, затем удаляет их. Он не подключается к HOSTiQ.
