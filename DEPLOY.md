# Самостоятельное размещение сайта

Для админки нужен полный проект, а не один HTML. В составе проекта должны быть `server.mjs`, `cms/`, `admin/`, `scripts/`, `site-data.mjs`, `cv-copy.mjs`, `style.css`, `app.js`, `assets/` и `package.json`.

Пароли, `.data/`, `.env` и другие рабочие данные не загружайте в открытый репозиторий. Пароль администратора выбирается после размещения.

## Namecheap VPS: Ubuntu без других сайтов

В комплекте `Dockerfile`, `compose.yaml`, `Caddyfile` и `.env.example`. Docker запускает Node.js-приложение и Caddy, который принимает запросы домена и автоматически получает HTTPS-сертификат. Контент и фото хранятся в отдельном Docker volume. Настройки рассчитаны на небольшой сайт на VPS с 1 CPU / 1 ГБ RAM: приложение ограничено 384 МБ, прокси — 128 МБ, логи ограничены по размеру.

### 1. Направить домен

Найдите публичный IPv4 VPS в панели Namecheap. В действующей DNS-панели домена создайте/измените запись:

```text
Type: A
Host: @
Value: IP_ВАШЕГО_VPS
TTL: Automatic
```

Если DNS обслуживает Namecheap BasicDNS, это Domain List → Manage → Advanced DNS → Host Records. Если указаны сторонние nameservers, запись меняется у соответствующего DNS-провайдера. Для этой инструкции используйте основной домен, например `mydomain.com`. Caddy должен быть доступен с Интернета на TCP 80 и 443.

### 2. Подключиться по SSH

```sh
ssh root@IP_ВАШЕГО_VPS
```

Используйте параметры подключения из панели VPS. Если выдан другой пользователь/порт, подставьте их. Пароль или SSH-ключ вводится локально, его не нужно передавать в чат.

### 3. Установить Docker в Ubuntu

```sh
sudo apt update
sudo apt install -y docker.io docker-compose-v2 git
sudo systemctl enable --now docker
docker --version
sudo docker compose version
```

Команды используют подписанные репозитории Ubuntu. Если пакет `docker-compose-v2` отсутствует в вашей версии ОС, не заменяйте его устаревшим `docker-compose`: уточните версию Ubuntu и установите актуальный Compose из официального репозитория Docker для неё.

Если используется UFW, разрешите веб-порты:

```sh
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

Эта инструкция не меняет настройки SSH и не включает/сбрасывает firewall.

### 4. Разместить полный проект в GitHub

Код должен быть загружен в `mansonansap/site-marketing` либо в ваш другой репозиторий, в выбранную ветку. Обязательны `server.mjs`, `cms/`, `admin/`, `scripts/`, исходные данные, ресурсы, package.json и Docker-файлы. Один HTML из переписки не содержит серверную админку.

Для развёртывания используется ветка `main` с полным проектом. Не загружайте `.data/`, `.env`, пароли и резервные копии рабочих данных.

### 5. Скачать проект на VPS

Если репозиторий публичный:

```sh
sudo mkdir -p /opt/marketing-cv
sudo chown "$USER":"$USER" /opt/marketing-cv
git clone https://github.com/mansonansap/site-marketing.git /opt/marketing-cv
cd /opt/marketing-cv
```

Для закрытого репозитория сначала настройте на VPS read-only GitHub Deploy Key, а затем используйте SSH-адрес репозитория. Приватный ключ и токены не кладите в код и не пересылайте в чат.

### 6. Указать домен

```sh
cp .env.example .env
nano .env
```

Замените пример:

```text
DOMAIN=mydomain.com
```

Без `https://`, `www` и завершающего слеша. В nano: Ctrl+O → Enter для сохранения, Ctrl+X для выхода.

### 7. Запустить

```sh
sudo docker compose up -d --build
sudo docker compose ps
```

Подождите запуска приложения и выдачи сертификата. DNS уже должен указывать на VPS, а 80/443 должны быть доступны. Откройте `https://mydomain.com`.

Если страница не открывается:

```sh
sudo docker compose logs --tail=80 app
sudo docker compose logs --tail=80 proxy
```

Не создавайте публичные ссылки на порт 3000: он доступен только внутри Docker-сети.

### 8. Создать администратора

```sh
sudo docker compose exec app npm run admin:create
```

Введите логин и пароль минимум из 12 символов. Затем откройте `https://mydomain.com/admin/` и войдите. Пароль вводится скрыто.

### 9. Наполнить сайт

В админке загрузите фото, заполните профиль, опыт, ссылки и материалы. Нажмите Сохранить → Предпросмотр → Опубликовать.

Проверьте, что данные переживают перезапуск:

```sh
sudo docker compose restart app
```

### 10. Обновления и резервные копии

После обновления кода в GitHub:

```sh
cd /opt/marketing-cv
git pull
sudo docker compose up -d --build
```

Рабочие данные остаются в томе `marketing-cv_cv-data`, сертификаты — в отдельных томах Caddy. Не удаляйте эти тома при обновлениях. Перед важными изменениями сохраняйте резервную копию `DATA_DIR`, включая фотографии. Экспорт JSON в админке сохраняет тексты и настройки, но не файлы изображений.

## Проверка после размещения

- Главная, статьи и проекты открываются по HTTPS.
- `/healthz` возвращает `{"ok":true}`.
- В `/admin/` работает вход, редактирование и загрузка фото.
- Сохранение не меняет публичную страницу до публикации.
- Предпросмотр показывает правки и требует входа.
- После публикации изменения видны посетителям.
- После перезапуска фото и тексты остаются.

Периодически сохраняйте резервную копию полного `DATA_DIR`, включая `uploads/`. Экспорт JSON в админке сохраняет тексты и настройки, но не сами фотографии.
